\subsection{The pinhole camera}
\label{subsec:ch3.pinhole}
%---------------------------------------------------------------------
% Merge the two sections
%---------------------------------------------------------------------
Before working processing images, it is important to understand the basic working of cameras how a camera maps a $3D$ point from a scene to a pixel.
Each point on a 3D image emits light in multiple directions. For a sensor receiving this light, each point on the sensor receives light from every point of the object, resulting in a blur 
across the sensor. This can be fixed with a barrier and a tiny hole (aperture) allowing only one or a small number of rays get through the aperture to the
sensor. Each point's rays therefore only land on a single sensor point, allowing for a clear image and a mapping from the 3D object to the 2D sensor. 
This is known as the pinhole camera model \citep{hataCS231ACourseNotes} and is shown in \autoref{fig:ch3.pinhole_model} below.

\begin{figure}[H]
	\centering
	\includegraphics[width=0.6\textwidth]{figs/Ch3/pinhole_model2.png}
	\caption[Placeholder Example]{\textbf{Pinhole Model.} Incoming rays with aperture and barrier.}
	\label{fig:ch3.pinhole_model}
\end{figure}
\


The following terms are used for the pinhole camera throughout this report \citep{hataCS231ACourseNotes,hartleyMultipleViewGeometry2004}:
\begin{itemize}
	\item \textbf{Camera centre} $O$: the pinhole, through which every ray passes. It is also called the optical centre or centre of projection.
	\item \textbf{Image plane} $\Pi'$: the plane of the sensor, on which the inverted image forms.
	\item \textbf{Focal length} $f$: the distance from $O$ to the image plane.
	\item \textbf{Optical axis}: the line through $O$ perpendicular to the image plane.
	\item \textbf{Principal point}: the point where the optical axis meets the image plane.
	\item \textbf{Virtual image plane} $\Pi'_v$: an imaginary plane a distance $f$ \textit{in front} of $O$. The image on it is identical to the sensor image except that it is not inverted, so it is the plane used in the derivations that follow.
	\item \textbf{Camera coordinate frame}:The \textit{camera frame} has its origin at $O$, with axes $\hat{\mathbf{x}}_c$, $\hat{\mathbf{y}}_c$ and $\hat{\mathbf{z}}_c$, where $\hat{\mathbf{z}}_c$ lies along the optical axis towards the scene.
	 A point in this frame has coordinates $\mathbf{M}_c = [X_c, Y_c, Z_c]^T$.
\end{itemize}


Suppose $\mathbf{M}_c = [X_c, Y_c, Z_c]^T$ is a point in the camera frame, and let $\mathbf{m}' = [x', y']^T$ be 
where it appears on the virtual image plane. Since every point on this plane lies at $Z = f$, only its first two coordinates are needed.
The image coordinates $(x', y')$ can be found from the scene coordinates using similar triangles, as shown in the cross-section of 
\autoref{fig:ch3.pinhole_detailed}.
The smaller triangle is shown in orange and the larger triangle shown in blue. Both are 
right-angled and share the angle at $O$, so they are similar triangles with their corresponding sides haiving equal ratios:
\begin{equation}
	\frac{x'}{f} = \frac{X_c}{Z_c}, \qquad \frac{y'}{f} = \frac{Y_c}{Z_c}
	\qquad\Longrightarrow\qquad
	x' = f\,\frac{X_c}{Z_c}, \qquad y' = f\,\frac{Y_c}{Z_c}.
	\label{eq:ch3.persp}
\end{equation}

	\caption[Similar triangles in the pinhole model]{\textbf{Similar triangles in the pinhole model.} Cross-section through the optical axis.
	 The triangle formed by $O$, the optical axis and the scene point $\mathbf{M}_c$ is similar to the triangle formed by $O$, 
	 the principal point and the image point $\mathbf{m}'$, which gives \autoref{eq:ch3.persp}.}
	\label{fig:ch3.pinhole_detailed}
\end{figure}
 

\autoref{eq:ch3.persp} are the equations of \textit{perspective projection} \citep{hataCS231ACourseNotes,hartleyMultipleViewGeometry2004}. 
From these equations two key observations can be made. Objects appear smaller with distance, 
since the image coordinates scale with $1/Z_c$. 
Secondly, and more importantly, depth is lost in the mapping from $3D$ to $2D$.
Every point along the ray through $\mathbf{M}_c$ projects to the same image point. Recovering depth requires a second 
viewpoint (\autoref{sec:ch3.stereo_geometry}). Setting $f = 1$ gives the \textit{normalised image coordinates}
\begin{equation}
	x = \frac{X_c}{Z_c}, \qquad y = \frac{Y_c}{Z_c},
	\label{eq:ch3.normcoord}
\end{equation}
which depend only on the direction of the ray, not on the lens or sensor \citep{hartleyMultipleViewGeometry2004}.
 
Real cameras replace the pinhole with a lens, which gathers more light while still focusing the rays from each point onto one sensor point.
A focused lens follows the same projection as \autoref{eq:ch3.persp}, with $f$ the lens-to-sensor distance \citep{hataCS231ACourseNotes}. 
As the lenses used in this project are fixed-focus (\autoref{sec:ch4.hardware}), this distance is constant and a single calibration holds for all images.

Because $Z_c$ appears in the denominator, \autoref{eq:ch3.persp} is nonlinear: it cannot be written as a matrix product, and scaling a point along its ray leaves its image unchanged rather than scaling it. Homogeneous coordinates restore linearity by deferring the division to a single final step, so that projection, rotation and translation can be written as matrices and chained together \citep{hartleyMultipleViewGeometry2004}.

%---------------------------------------------------------------------
\subsection{Homogeneous coordinates}
\label{subsec:ch3.homogeneous}
%---------------------------------------------------------------------
The division by $Z_c$ makes \autoref{eq:ch3.persp} nonlinear, so it cannot be written as a matrix. Homogeneous coordinates
solve this by adding an extra coordinate that holds the scale \citep{hartleyMultipleViewGeometry2004}. A 2D point $[x, y]^T$
becomes $\tilde{\mathbf{m}} = [x, y, 1]^T$, and a 3D point becomes $\tilde{\mathbf{M}} = [X, Y, Z, 1]^T$. Any multiple of a
homogeneous vector represents the same point, so $[2x, 2y, 2]^T$ still represents $[x, y]^T$; the point is recovered by dividing
by the last element. This lets the division be left until the end, so that projection, rotation and translation can all be
written as matrices and chained together. Perspective projection then becomes:
\begin{equation}
	Z_c
	\begin{bmatrix} x' \\ y' \\ 1 \end{bmatrix}
	=
	\begin{bmatrix}
		f & 0 & 0 & 0 \\
		0 & f & 0 & 0 \\
		0 & 0 & 1 & 0
	\end{bmatrix}
	\begin{bmatrix} X_c \\ Y_c \\ Z_c \\ 1 \end{bmatrix}.
	\label{eq:ch3.persp_homog}
\end{equation}
The matrix product gives $[fX_c, fY_c, Z_c]^T$, and dividing by its last element returns \autoref{eq:ch3.persp}. The unknown
scale, here $Z_c$, is written $\lambda$ in general.
%---------------------------------------------------------------------
\subsection{Intrinsic parameters}
\label{subsec:ch3.intrinsics}
%---------------------------------------------------------------------
\autoref{eq:ch3.persp} gives image positions in millimetres, measured from the principal point. 
A digital image instead uses pixels $\mathbf{m} = [u, v]^T$, measured from the top-left corner. 
The intrinsic matrix $\mathbf{K}$ converts between the two \citep{zhangFlexibleNewTechnique2000}:
\begin{equation}
	\tilde{\mathbf{m}} = \mathbf{K}\,\tilde{\mathbf{x}},
	\qquad
	\mathbf{K} =
	\begin{bmatrix}
		\alpha & \gamma & u_0 \\
		0      & \beta  & v_0 \\
		0      & 0      & 1
	\end{bmatrix},
	\label{eq:ch3.K}
\end{equation}
where $\tilde{\mathbf{x}} = [x, y, 1]^T$ are the normalised coordinates. Its parameters are:
\begin{itemize}
	\item $\alpha$ and $\beta$: the focal length in pixels, horizontally and vertically, equal to $f$ multiplied by the number of pixels per millimetre.
	\item $(u_0, v_0)$: the principal point in pixels, usually close to the image centre.
	\item $\gamma$: the skew between the sensor axes. It is negligible for modern sensors 
	and set to zero in OpenCV \citep{opencvCameraCalibration3D}.
\end{itemize}

OpenCV writes $\alpha$, $\beta$, $u_0$ and $v_0$ as $f_x$, $f_y$, $c_x$ and $c_y$. 
Since $\mathbf{K}$ is invertible, $\mathbf{K}^{-1}\tilde{\mathbf{m}}$ converts a pixel back into the direction of its ray. 
For the StellarHD cameras (\autoref{sec:ch4.hardware}), the 3.0\,mm lens and 3\,$\mu$m pixels give a nominal focal length of about 1000 pixels in air and X 
in water.


%---------------------------------------------------------------------
\subsection{Extrinsic parameters}
\label{subsec:ch3.extrinsics}
%---------------------------------------------------------------------
Scene points are usually given in a \textit{world frame} fixed in the scene.
The \textit{extrinsic parameters} describe the  rotation and translation,
 from the world frame to the camera frame \citep{hartleyMultipleViewGeometry2004}:
\begin{equation}
	\mathbf{M}_c = \mathbf{R}\,\mathbf{M}_w + \mathbf{t}
	\quad\Longleftrightarrow\quad
	\tilde{\mathbf{M}}_c = \mathbf{T}_{cw}\,\tilde{\mathbf{M}}_w,
	\qquad
	\mathbf{T}_{cw} =
	\begin{bmatrix}
		\mathbf{R} & \mathbf{t} \\
		\mathbf{0}^T & 1
	\end{bmatrix},
	\label{eq:ch3.extrinsic}
\end{equation}
where $\mathbf{R}$ is a $3 \times 3$ rotation matrix and $\mathbf{t}$ is a translation vector.
 Together they have six degrees of freedom: three angles and three distances. $\mathbf{R}$ rotates without stretching or mirroring.
  Note that $\mathbf{t}$ is the position of the world origin seen from the camera, not the position of the camera itself, which is $-\mathbf{R}^T\mathbf{t}$. In this report, 
  $\mathbf{T}_{ab}$ maps points from frame $b$ into frame $a$, so $\mathbf{T}_{cw}$ corresponds to the \texttt{T\_cam\_world} poses given in \autoref{ch:reconstruction}. 
The intrinsics stay fixed for a camera, while the extrinsics change with every image.



%---------------------------------------------------------------------
\subsection{The projection chain}
\label{subsec:ch3.projection}
%---------------------------------------------------------------------
Combining the extrinsics, perspective projection and intrinsics gives the pinhole camera model \citep{zhangFlexibleNewTechnique2000}:
\begin{equation}
	\lambda\,\tilde{\mathbf{m}} = \mathbf{K}\,[\mathbf{R} \mid \mathbf{t}]\,\tilde{\mathbf{M}}_w = \mathbf{P}\,\tilde{\mathbf{M}}_w,
	\label{eq:ch3.P}
\end{equation}
where $\lambda$ is the depth $Z_c$ and $\mathbf{P}$ is the $3 \times 4$ \textit{projection matrix}. 
This assumes an ideal lens. Lens distortion cannot be written as a matrix, so it is applied separately to
 the normalised coordinates \citep{heikkilaFourstepCameraCalibration1997,opencvCameraCalibration3D}.
  The full projection is therefore the four steps of \autoref{fig:ch3.projection_chain}, written
\begin{equation}
	\mathbf{m} = \pi(\mathbf{M}_w;\; \mathbf{K}, \bm{\kappa}, \mathbf{R}, \mathbf{t}),
	\label{eq:ch3.pi}
\end{equation}
where $\bm{\kappa}$ holds the distortion coefficients. This is the model that calibration estimates. 
Run in reverse, a pixel gives only a ray, because the depth $Z_c$ is lost.

\subsection{Lens distortion}
\label{subsec:ch3.distortion}
%---------------------------------------------------------------------
Real lenses do not follow the pinhole model exactly. The main differnce is \textit{radial distortion}. For real lenses, magnification can vary slightly
 with distance from the image centre,  so points are pushed towards or away from the principal point. This bends straight lines outwards (\textit{barrel}) 
 or inwards (\textit{pincushion}), as shown  in \autoref{fig:ch3.radial_distortion} \citep{brownCloseRangeCameraCalibration1971}. 
A smaller \textit{tangential} distortion occurs when the lens is not perfectly centred or parallel to the sensor \citep{brownDecenteringDistortionLenses1966}.
\begin{figure}[H]
	\centering
	\includegraphics[width=0.85\textwidth]{figs/Ch3/radial_distortion.pdf}
	\caption[Radial lens distortion]{\textbf{Radial lens distortion.} A square grid (a) undistorted, (b) with barrel distortion and (c) with pincushion distortion, from the first radial term of \autoref{eq:ch3.bc_x}. Dashed lines show the undistorted grid; the cross marks the principal point.}
	\label{fig:ch3.radial_distortion}
\end{figure}
 

Both effects are described by the \textit{Brown--Conrady} model \citep{brownDecenteringDistortionLenses1966,brownCloseRangeCameraCalibration1971}, in the form used by OpenCV \citep{heikkilaFourstepCameraCalibration1997,opencvCameraCalibration3D}.
Different methods for mapping normalised coordinates to distorted coordinates are described and compared in \autoref{sec:ch4.compensationstage}.

\section{Camera calibration}
\label{sec:ch3.calibration}

Calibration estimates the the intrinsics $\mathbf{K}$ and distortion $\bm{\kappa}$, shared by all images, and a pose $(\mathbf{R}_i, \mathbf{t}_i)$ for each image $i$. It uses a target of known geometry. The world coordinates $\mathbf{M}_j$ of points on the target are known from its design, and their pixel positions $\mathbf{m}_{ij}$ are detected in each image. Each detected point gives two equations, so a set of images with many points over-determines the unknowns, which are then found by least squares \citep{zhangFlexibleNewTechnique2000}.

%---------------------------------------------------------------------
\subsection{Targets and corner detection}
\label{subsec:ch3.targets}
%---------------------------------------------------------------------
Checkerboard targets require the whole board to be visible, so that each corner can be identified by its position in the grid. Fiducial markers such as AprilTags instead encode a unique ID in each tag, so every detected corner can be matched to its known position even when the board is partly out of view \citep{olsonAprilTagRobustFlexible2011}. This project uses an AprilGrid, a board of AprilTags \citep{furgaleUnifiedTemporalSpatial2013}, as AprilTags were the most reliably detected of the markers tested in turbid water by \citet{dossantoscesarEvaluationArtificialFiducial2015}. Detection thresholds the image, searches for square outlines and decodes each tag's ID, after which the corners are refined to sub-pixel accuracy \citep{wangAprilTagEfficientRobust2016}. The detector settings are given in \autoref{sec:ch4.calibration}.

%---------------------------------------------------------------------
\subsection{Zhang's method}
\label{subsec:ch3.zhang}
%---------------------------------------------------------------------
Zhang's method works in two stages \citep{zhangFlexibleNewTechnique2000}. Because the board is flat, the mapping from board points to image points in each image is a simple plane-to-plane transformation, a \textit{homography}. Its form depends on both $\mathbf{K}$ and the board's pose, so the homographies from three or more images of the board at different angles are enough to calculate $\mathbf{K}$ and each pose directly. This first estimate ignores lens distortion and noise, so it is only a starting point.

In the second stage, all parameters, including distortion, are refined together by minimising the \textit{reprojection error}: the distance between each detected corner and where the camera model predicts it should appear,
\begin{equation}
	E = \sum_{i}\sum_{j} \left\| \mathbf{m}_{ij} - \pi(\mathbf{M}_j;\, \mathbf{K}, \bm{\kappa}, \mathbf{R}_i, \mathbf{t}_i) \right\|^2 .
	\label{eq:ch3.reproj}
\end{equation}
As the camera model is nonlinear, this is solved iteratively with the Levenberg--Marquardt algorithm \citep{marquardtAlgorithmLeastSquaresEstimation1963}. The fit is reported as the root-mean-square (RMS) reprojection error in pixels. Once the camera is calibrated, the same minimisation over the pose alone gives the position of the board in a new image, known as the Perspective-n-Point (PnP) problem \citep{hartleyMultipleViewGeometry2004}. This is how held-out images are scored in \autoref{ch:experiment}.

%---------------------------------------------------------------------
\subsection{Stereo calibration}
\label{subsec:ch3.stereo_calib}
%---------------------------------------------------------------------
In a stereo pair, both cameras view the same board. If $(\mathbf{R}_l, \mathbf{t}_l)$ and $(\mathbf{R}_r, \mathbf{t}_r)$ are the board's poses in the left and right cameras, the rigid transformation from the left camera frame to the right is \citep{opencvCameraCalibration3D}:
\begin{equation}
	\mathbf{R}_{rl} = \mathbf{R}_r\,\mathbf{R}_l^T, \qquad \mathbf{t}_{rl} = \mathbf{t}_r - \mathbf{R}_{rl}\,\mathbf{t}_l .
	\label{eq:ch3.stereo_extrinsics}
\end{equation}
As the cameras are rigidly mounted, this transformation is the same for every image pair. It is refined together with both cameras' parameters by minimising the reprojection error in both images. The distance between the camera centres, $B = \|\mathbf{t}_{rl}\|$, is the \textit{baseline}.

%---------------------------------------------------------------------
\subsection{Calibrating underwater}
\label{subsec:ch3.underwater_calib}
%---------------------------------------------------------------------
Underwater cameras view the scene through a window in their housing. With a flat window, or \textit{port}, light passes from water through glass into air, bending at each surface according to Snell's law \citep{hechtOptics2017}:
\begin{equation}
	n_w \sin\theta_w = n_g \sin\theta_g = n_a \sin\theta_a ,
	\label{eq:ch3.snell}
\end{equation}
where $n$ is the refractive index and $\theta$ the angle to the port normal in water, glass and air. The glass only shifts rays sideways, so the overall bending depends on water and air. Near the optical axis, $\sin\theta \approx \tan\theta$, so a ray arriving at angle $\theta_w$ reaches the camera at $\tan\theta_a \approx n \tan\theta_w$, where $n = n_w / n_a \approx 1.33$. The image is therefore magnified by about 1.33: the effective focal length increases and the field of view narrows \citep{shortisCalibrationTechniquesAccurate2015}. Further from the axis this approximation breaks down and the magnification grows, an error that increases towards the image edges much like pincushion distortion.

Refraction also breaks the pinhole assumption. Traced back into the water, the refracted rays no longer pass through a single point, so the camera is no longer \textit{central} \citep{treibitzFlatRefractiveGeometry2012}. Instead, every ray passes through one line, the port normal through the camera centre, which makes it an \textit{axial} camera \citep{agrawalTheoryMultilayerFlat2012}. A pinhole model fitted underwater is therefore only exact at certain distances, and its errors depend on how far away the scene is \citep{treibitzFlatRefractiveGeometry2012}.

Underwater calibration methods fall into three groups \citep{shortisCalibrationTechniquesAccurate2015}:
\begin{enumerate}
	\item \textbf{Absorb refraction into the lens model.} Calibrating in water with a standard model lets the distortion coefficients absorb most of the refraction. This is simple and works with any housing, but is most accurate over the distances it was calibrated at \citep{shortisCalibrationTechniquesAccurate2015}.
	\item \textbf{Calibrate in air and correct separately.} The camera is calibrated in air, and refraction is corrected using the port geometry and the refractive index of the water, as in the Pinax model \citep{luczynskiPinaxmodelAccurateEfficient2017}.
	\item \textbf{Model refraction explicitly.} The non-central ray geometry is modelled directly, for example by ray tracing through the port \citep{agrawalTheoryMultilayerFlat2012}. This is the most physically accurate, but more complex and often specific to one housing.
\end{enumerate}
The methods tested in this project are described in \autoref{sec:ch4.compensationstage} and compared in \autoref{ch:experiment}.

\subsection{Forward vs back-projection}

a pixel to a 3D ray. Within the context of this project, forward projection is used for correcting
distortion and backwards projection for estimating a camera pose and reconstruction.

% Reinhard Klette
Intrinsic (camera specific) and extrinsic parameters are required.
Intrinsic: (effective) focal length, dimensions of the sensor matrix, sensor cell size or aspect ratio of sensor height to width, radial distortion parameters, coordinates of the principal point, or the scaling factor.

\subsubsection{Camera lenses}
The pinhole model assumes that all rays pass through a singular point. In reality the aperture must be large enough to let enough light in
for a usable bright image. This larger aperture however, result in multiple incoming rays from a single point and blurring as noted in (SEC REF). 
The solution to this is a lens. 

A lens refracts the multiple rays from a single $3D$ point so that they converge to a single point on the sensor. This converging only works for a set 
distance from the camera, meaning further or closer points appear to be "out of focus" \citet{hataCS231ACourseNotes}. 

A thin lens follows the same prospective projection equations as \autoref{eq:ch3.persp}, with \textit{f} being the distance between the lens and the sensor
\citet{hataCS231ACourseNotes}. Real non-ideal lenses howver produce magnification that varies with distance from the optical axis. This bends 
bends straight lines in the image, producin radial distortion. (REF HERE SOMEWHERE?)

\section{Camera calibration}
\label{sec:ch3.calibration}
%=====================================================================
\textbf{Designing a Calibration Method:}
% Zhang mentions Three-dimensional reference object-based calibration and Self-calibration separately
Points $(X_w, Y_w, Z_w)$ on the calibration rig (e.g. corners of the squares) or calibration marks are known by their physically measured coordinates. Determine a corresponding $(x,y)$ if possible with sub-pixel accuracy. That is the projection of $(X_w, Y_w, Z_w)$ in the world plane. E.g. 100 points, 100 equations.

The equations defining our camera model contain $X_w$, $Y_w$, $Z_w$, $x$ and $y$ as known values, and the intrinsic and extrinsic camera parameters as unknowns. The resulting equation system (necessarily nonlinear due to central projection or radial distortion) needs to be solved for the specified unknowns. Over-determined situations provide stability of the numerical solution scheme.

\subsection{Calibration targets and AprilTag fiducials}
\label{subsec:ch3.targets}

\textbf{Manufacturing a calibration board:}
Rigid B\&W pattern common, at least 7x7 squares large enough such that the minimum size when recorded on the image is at least 10x10 pixels (i.e. having a camera with effective focal length \textit{f}, this allows us to estimate the size \textit{axa} of each square assuming a distance of $b$ m between camera and board).

\textbf{Localising Corners in the Checkerboard:}
 Calibration marks are the corners of squares (approximated by the intersection points of grid lines, thus defining corners potentially with sub-pixel accuracy).

 Mention of the Hough space method for detecting line segments requires that lens distortion has been removed from recorded images prior to applying the Hough-space method. Images with lens distortion will show bent lines rather than straight grid lines.

 \textbf{Localising Calibration marks:}
 Can also be defined by circular or square dots. Popular if same location, can be permanently painted on walls or other static surfaces.

 Sub-pixel accuracy by calculating the centroid of this region (example given).

Common calibration techniques implement checkerboards as explained in SECTION X. Due to the difficulties (leaning off boat) in underwater in-situ calibration, it was chosen to use calibration boards with fiducial markers. Fiducial markers are "landmarks" to aid in computer vision models. Unique IDs are "encoded in their structure following a pre-defined pattern system and provide a means to implement reliable pose estimation of the marker with respect to the camera."

\subsection{AprilTag detection stages}
\label{subsec:ch3.detectionstages}
%---------------------------------------------------------------------
Tags are detected with OpenCV's \texttt{ArucoDetector} using the AprilTag 36h11 dictionary. The detector has four stages:
\begin{enumerate}
	\item \textbf{Thresholding.} The grayscale image is converted to black and white with adaptive thresholding. This compares each pixel to its local neighbourhood rather than to a global level, which is particularly useful for uneven lighting across the board.
	\item \textbf{Candidate search.} Looks for contours indicative of the outer black square of a tag (rough square, 4 sides, reasonable size).
	\item \textbf{Decoding.} Each candidate is morphed into a square shape and the internal white/black grid is read off. Candidates without a valid code are rejected.
	\item \textbf{Output.} For each accepted tag, the detector reports the id and the pixel positions of the corners.
\end{enumerate}
