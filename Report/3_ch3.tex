\subsection{Model parameters: global, local and discrete}
%---------------------------------------------------------------------
\cite{sturmCameraModelsFundamental2011} further separates models into global, local and discrete
models. This separation regards how the model's parameters describe the image.
Global models (e.g.\ Pinhole) have parameters for the whole image, local separates parameters sets
for different section of the image. Discrete models have their projection function sampled at
different points, e.g.\ one per pixel. For discrete models, interpolation needed for back-projecting
to non-sampled image points, essentially making them local models.

The standard terminology for a pinhole camera model used in this report is as follows:
\begin{itemize}
	\item \textbf{Camera center} $O$: the pinhole, the single point through which all rays pass.
    \item \textbf{Focal length}, $f$: distance from $O$ to the image plane. % Check difference with effective and actual
    \item \textbf{Optical axis}: 
    \item \textbf{Virtual Principal point}: 
    \item \textbf{Principal point}: 
	\item \textbf{Object plane}, $\Pi$: The plane containing the object
    \item \textbf{Image plane}, $\Pi'$: the sensor, on which the image is inverted.
    \item \textbf{Virtual image plane}, $\Pi'_v$: imaginary plane placed at a distance $f$ \textit{in front} of $O$, between the pinhole and object. 
		The image formed on this plane is identical to the real sensor iamge, except not inverted. 
    \item \textbf{Camera Coordinate system $(i,j,k)$:} a $3D$ coordinate frame with its origin at $O$. The $k$ axis is perpendicular to the image plane, 
	pointing along the viewing direction. Coordinates within this frame have are written (Xc, Yc, Zc).
\end{itemize}

Suppose $M_c = [X_c, Y_c, Z_c]^T$ is a object point in the 3D world expressed in the camera coordinate frame. This point's projection onto the 2D virtual
in the image plane is $\textbf{m'}=[x',y']^T$. To understand this mapping between the 3D world and the sensor image, we need to define the relationship between
 $\textbf{M}_c$ and $m'$.

 To determine this relationship, we can use the properties of similar triangles. 
\autoref{fig:ch3.pinhole_detailed} shows the two similar triangles. The smaller  triangle is formed by the camera centre $O$, 
the point $(0, 0, f)$ where the  optical axis meets the virtual image plane, and the projected point $\mathbf{m}'$. 
The larger triangle is formed by $O$, the point $(0, 0, Z_c)$ on the optical axis, and the 3D point $\mathbf{M}_c$. These triangles are both right angled
triangles with a common angle, making them similar. Similar triangles have equal ratios between corresponding sides meaning

\begin{equation}
	\frac{x'}{f} = \frac{X_c}{Z_c}, \qquad \frac{y'}{f} = \frac{Y_c}{Z_c}
	\qquad\Longrightarrow\qquad
	x' = f\,\frac{X_c}{Z_c}, \qquad y' = f\,\frac{Y_c}{Z_c}.
	\label{eq:ch3.persp}
\end{equation}

These make the equations of \textit{perspective projection} \citep{hataCS231ACourseNotes}. They show how the $2D$ image coordinates of a 3D point can be
defined by its $X_c$ and $Y_c$ coordinates scald by $\frac{f}{Z_c}$. This has two direct consequneces:
\begin{itemize}
	\item The further away an object is (increased $Z_c$), the smaller it appears in the image as $x'$ and $y'$ shrink towards the center of the image
	\item Depth is lost when the image is formed. The projection takes $(X_c,Y_c,Z_c)$ and outputs $(x'.y')$. The pixel only tells you the ray the point lands on,
	 not where on the ray. TO do this you ned two cameras (see section X, maybe take this into stereo camera justification section).
\end{itemize}

These equations can be simplified setting $f=1$ to produce the \textit{normalised image coordinates}:
\begin{equation}
	x = \frac{X_c}{Z_c}, \qquad y = \frac{Y_c}{Z_c}
	\label{eq:ch3.normcoord}
\end{equation}

\subsubsection{Camera lenses}
The pinhole model assumes that all rays pass through a singular point. In reality the aperture must be large enough to let enough light in
for a usable bright image. This larger aperture however, result in multiple incoming rays from a single point and blurring as noted in (SEC REF). 
The solution to this is a lens. 

A lens refracts the multiple rays from a single $3D$ point so that they converge to a single point on the sensor. This converging only works for a set 
distance from the camera, meaning further or closer points appear to be "out of focus" \citet{hataCS231ACourseNotes}. 

A thin lens follows the same prospective projection equations as \autoref{eq:ch3.persp}, with \textit{f} being the distance between the lens and the sensor
\citet{hataCS231ACourseNotes}. Real non-ideal lenses howver produce magnification that varies with distance from the optical axis. This bends 
bends straight lines in the image, producin radial distortion. (REF HERE SOMEWHERE?)

Points $(X_w, Y_w, Z_w)$ on the calibration rig (e.g. corners of the squares) or calibration marks are known by their physically measured coordinates. The equations defining our camera model contain $X_w$, $Y_w$, $Z_w$, $x$ and $y$ as known values, and the intrinsic and extrinsic camera parameters as unknowns. The resulting equation system (necessarily nonlinear due to central projection or radial distortion) needs to be solved for the specified unknowns. Over-determined situations provide stability of the numerical solution scheme.

\subsection{AprilTag detection stages}
\label{subsec:ch3.detectionstages}
%---------------------------------------------------------------------
Tags are detected with OpenCV's \texttt{ArucoDetector} using the AprilTag 36h11 dictionary. The detector has four stages:
\begin{enumerate}
	\item \textbf{Thresholding.} The grayscale image is converted to black and white with adaptive thresholding. This compares each pixel to its local neighbourhood rather than to a global level, which is particularly useful for uneven lighting across the board.
	\item \textbf{Candidate search.} Looks for contours indicative of the outer black square of a tag (rough square, 4 sides, reasonable size).
	\item \textbf{Decoding.} Each candidate is morphed into a square shape and the internal white/black grid is read off. Candidates without a valid code are rejected.
	\item \textbf{Output.} For each accepted tag, the detector reports the id and the pixel positions of the corners.
\end{enumerate}
