and tests the AprilGrid detection pipeline as well as three different underwater compensation techniques. Calibration images were
taken both in air and underwater. The in-air calibration provides a baseline for analysing the effect that the underwater environment

The StellarHD cameras do not support single-shot image. Each frame is extracted from the .mkv video file using
\texttt{extract\_stereo\_frame.py}. As there is no hardware synchronisation between the two stellarHD cameras,
 the script pairs left and right framews with the closest timestamp, rejecting pairs if with a difference above a configurable 
 threshold (default 10\,ms). Since the ROV is stationary at each set position, a 10\,ms offset
causes negligible relative motion between the two views. \texttt{extract\_stereo\_framep.py} allows for manual frame selection 
or selecting frames at set steps (e.g. every 10th frame)

\subsubsection{Calibraion analysis metrics}
Optimising for calibration requires careful consideration to avoid degrading the accuracy of the calibration. Selectivly choosing frames to reduce RMS error results in losing calibration
coverage. Harder to detect tags may increase RMS errors due to higher noise with their detections, resulting in worse RMS error therefore punishing the algortithms for a more accurate output.
To avoid this, four metrics are used to evaluate the calibration's algorithm's effectiveness:
\begin{enumerate}
    \item \textbf{Tag detection rate:} number of AprilTags detected, as a fraction of the total board tags.
    \item \textbf{Mean per-image RMS:} reprojection error computed separately for each image, then averaged over all images.
    \item \textbf{Overall RMS:} reprojection error over all detected corners, as returned by \texttt{calibrateCameraExtended}.
    \item \textbf{Parameter uncertainty:} standard deviations of the intrinsic parameters, as returned by \texttt{calibrateCameraExtended}.
    \item \textbf{Measurement accuracy:} error in tag size measured by stereo triangulation of a different AprilTag target at distances of 50--250\,cm.
    \item \textbf{Matched-tag RMS:} reprojection error computed only over tags detected in all of the compared calibrations.
\end{enumerate}

\subsubsection{Brown-Conrady}
% Refernce doces: https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html
% Explain the baseic maths
The Brown-Conrady is a camera model capable of correcting lens induced geometric 
distortions \citet{xuComprehensiveOverviewFishEye2024}.The model handles radial distortion (barrel and pincushion) through
 multiplying each point by $(1 + k_1 r^2 + k_2 r^4 + k_3 r^6)$, where $r$ is the distance from the
image centre and $k_i$ are the radial coefficients. Tangential distortion, caused
by the lens not being perfectly lined up with the sensor, is handled by adding an
offset controlled by $p_1$ and $p_2$. Joining together, this gives: 
\begin{align}
x_d &= x\,(1 + k_1 r^2 + k_2 r^4 + k_3 r^6) + 2p_1 x y + p_2\,(r^2 + 2x^2) \\
y_d &= y\,(1 + k_1 r^2 + k_2 r^4 + k_3 r^6) + p_1\,(r^2 + 2y^2) + 2p_2 x y
\end{align}
where $(x, y)$ are the undistorted coordinates, $r = \sqrt{x^2 + y^2}$, and
$(x_d, y_d)$ are the distorted coordinates.

OpenCV implements this through \texttt{cv2.calibrateCamera}, using \citet{zhang}'s method for an initial estimate followed by
 Levenberg-Marquart optimisation to refine all parameters.  \cite{CvCalibrateCameraAuroraVision}.

 % REF https://docs.adaptive-vision.com/studio/filters/CameraCalibrationAnd3DReconstruction/cvCalibrateCamera.html


\subsubsection{Kannala-Brandt}
% https://docs.opencv.org/4.13.0/db/d58/group__calib3d__fisheye.html
% Explan the maths basic with references
The Kannala-Brandt distortion model is an extension of the standard Brown-Crandy model, providing a more accurate distortion
representation for wide-angle lenses. Instead of a single pinhole projection model ($x=f\tan\theta$),
 it approximates four different projection models with a polynomial in the angle $\theta$ of the incoming light ray:
\begin{equation}
r(\theta) = k_1\theta + k_2\theta^3 + k_3\theta^5 + k_4\theta^7 + k_5\theta^9
\end{equation}
Linking the radial distortion into the $\theta$ instead of the distance $r$, allows the model to work for wider fields of view 
$(r=\tan\theta)$ grows towards infinity as $\theta$ approaches $90^\circ$.

OpenCV uses the simpler version in \texttt{cv2.fisheye.calibrate}:
\begin{align}
\theta_d &= \theta\,(1 + k_1\theta^2 + k_2\theta^4 + k_3\theta^6 + k_4\theta^8) \\
(x_d,\, y_d) &= \frac{\theta_d}{r}\,(x,\, y)
\end{align}
It generates vector distortion coefficients, $(k1,k2,k3,k4)$ \cite{OpenCVFisheyeCamera}.

\subsubsection{Brown-Crady + axial shift (non single viewpoint assumption)}
% DONE BY 5:30
% Assumptions made by the pinhole (and Brown-Conrady) models regarding incoming light and center - single viewpoint
% Refraction bends the rays
% Different angles, cross at different points , edge futher forward or back
% 

The pinhole model assumes all incoming light refracts through the principle point at the center of the virtual image plane, making
a single viewpoint assumption. Refraction however can cause incident rays to bend, meaning rays further towards the edge
crossing either further forward or backwards. This can cause what( ref) literature, you said it can cause distance dependent error).
To test this, a similar approach to X( Ref) is tested

To test whether the aquagon lenses produce a single viewpoint, Brown-Conrady can be adapted to include an axial shift. A ray needs
a direction and a starting point. The direction is still the normal Brown-Conrady direction $(x,y,1)$. The
starting point, however, can be shifted from the origin along the optical axis: $\mathbf{o}(r)=(0,0,\Delta z(r))$. The shift depends on how
far the ray is from the centre:
\begin{equation}
\Delta z(r) = a_1 r^2 + a_2 r^4, \qquad r = \sqrt{x^2 + y^2}.
\end{equation}
If $a_1=a_2=0$, every ray starts at the origin and it is a standard Brown-Conrady. If $a_1$ and $a_2$ parameters do not
reduce error on held-out images, the extra shift isnt helping and the camera behaves as a single viewpoint camera.

The implemtation of this can be seen in the appendix (here for now)
% TODO: Switch code snippet gor algorithmic chart

\begin{lstlisting}[language=Python, caption={Brown-Conrady with axial ray shift: projection and fit (condensed from \texttt{models.py}).}, label={lst:axial}]
def dz(r, a1, a2):
    return a1 * r**2 + a2 * r**4            # axial shift (mm), zero on the axis

def normalised(X, a1, a2):
    """Ray direction (x, y) of camera-frame points X (N, 3)."""
    rho, Z = np.hypot(X[:, 0], X[:, 1]), X[:, 2]
    r = rho / Z                              # pinhole start
    for _ in range(8):                       # Newton: r (Z - dz(r)) = rho
        f  = r * (Z - dz(r, a1, a2)) - rho
        df = Z - dz(r, a1, a2) - r * (2*a1*r + 4*a2*r**3)
        r  = r - f / df
    return X[:, :2] / (Z - dz(r, a1, a2))[:, None]

def project(X, K, D, a1, a2):
    xy = normalised(X, a1, a2)
    rays = np.hstack([xy, np.ones((len(xy), 1))])
    return cv2.projectPoints(rays, np.zeros(3), np.zeros(3), K, D)[0]   # OpenCV distortion

# Fit: start from cv2.calibrateCamera (a1 = a2 = 0), then bundle-adjust

\subsubsection{Held out error and split training}
\label{sec:heldout}
Each method was scored on recordings it was not trained on. For every combination of two of the eight underwater
recordings (28 splits), the method was fitted on the other six and tested on the two held out, so every test
image comes from a sweep the model never saw (Appendix~\ref{app:heldout}). For each test image the intrinsics
are fixed, the board pose is fitted, and the held-out error is the RMS distance between the detected and
reprojected corners. Results are the mean over the 28 splits, and two methods are compared on the same splits,
a difference being within noise when the range of their 28 paired differences contains zero.


\subsubsection{Reprojection Error on the held-out recordings}
\textbf{Cross-validation}. Each method is scored on recordings it was not trained on. The held-out error is the RMS reprojection error
of the calibration measured on images that were withheld from its training. The data is split into training and
test sets to test how well the calibration predicts unseen data. For the calibration data set, there are 28 splits
with two of the eight sets held out. The results are the mean over the 28 splits. The full sweep of training 
splitts can be found in  (Appendix~\ref{app:heldout}). This cross-validation approach allows for accurate comparison
because testing on unseen recordings does not reward the models which over-fit the training data, averages over 28 splits,
and removes bias based on which set of recordings are held out.

\textbf{Zone split}. The analysis is split into zones based on how far each corner lies from the principal point, to analyse distortion and
refraction, which both grow towards the edges of the image. The zones are defined using a normalised radius. First, the
divisor $R_{\max}$ is set to the distance from the principal point to the farthest image corner (the top-right corner,
pixel $(1600, 0)$). The normalised radius of a detected corner is then
\begin{equation}
r = \frac{\lVert \mathbf{p} - \mathbf{c} \rVert}{R_{\max}},
\end{equation}
where $\mathbf{p}$ is the corner's pixel position and $\mathbf{c}$ is the principal point, so that $r = 0$ at the
optical centre and $r = 1$ at the farthest corner. The image is divided into three zones: centre ($r < 0.33$),
mid ($0.33 \le r < 0.66$) and outer ($r \ge 0.66$).

\textbf{Distance split}. The results are further split into near and far bands by board distance: near covers boards at 200--800\,mm and far
covers boards at 1000--1500\,mm. For the near and far comparisons, only the centre zone of the image is compared because
further boards appear small and dont reach the outer zones.

\subsubsection{Stereo scale}
% Explain what is computed and compared
Held-out stereo pairs are triangulated with each techniques two cameras and its stereo intrinsics. The central models (T1-T4) use 
\texttt{cv2.triangulatePoints} on the normalised rays, however T5 cannot use this method as it does not have a single P matrix to describe it. 
T5 uses midpoint triangulation. Due to small errors in corner detection and calibration, the two rays pass close to eachother without 
intersecting. The midpoint triangulation method finds the shortest segment connecting the two and takes the midpoint as the $3D$ point.
As a check, with $a_0$ and $a_1$ set to zero (making T5 central), the midpoint method agreed with \texttt{cv2.triangulatePoints} to within $10^{-6}$\,mm.

Each pair of AprilGrid corners are $250-400$mm  apart and are used as a "scale bar". Error is determined from the subtraction of true length and measured length 
from $3D$.
