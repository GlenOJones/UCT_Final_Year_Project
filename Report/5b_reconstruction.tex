\subsection{Using Tag poses}
Apriltags are useful beyond creating an occlusion freidnly calibration board. Placing apriltags within a scene, Like in figure X,
create easily identifianble locations, from which their 3D location measurements allow camea relative position to be calculated in following steps,
implemented through \texttt{tag\_poses.py}:
\begin{enumerate}   % TODO: MAKE INTO A SLIDING DIAGRAM
    \item \textbf{Find tag corners (L \& R):} Detect each AprilTag and locate its four corners.
    \item \textbf{Triangulate corners:} Convert each matched corner into a 3D point in the left camera frame.
    \item \textbf{Fit the tag layout:} Combine overlapping observations from all frames into one map.
    \item \textbf{Fit layout to frame:} For each frame, find the rotation and translation that line the map up with the measured corners.
    \item \textbf{Pose per frame:} The Step 4 transform is \texttt{T\_cam\_board}, and its inverse gives the camera's pose in the board frame.
\end{enumerate}

\subsection{ICP}
ICP (Iterative Closest Point) as explained in intro, is a standard technique for this ? is it?
It uses the shape of each frames $3D$ point cloud to estimate camera motion Each cloud is slid and rotated until it matches the previous one.
The amount of movement between clouds is the amount the camera has moved. It works one frame at a time, looping back for the next frame.

\begin{enumerate}
    \item \textbf{Depth points (per frame):} Each frame's stereo depth map is turned into a 3D point cloud, one point per valid pixel. This is done using \texttt{depth\_frames.py}. The quality of the stereo depth map feeds into ICP.
    \item \textbf{Thinning of the cloud:} Each cloud has too many points, so it is thinned to one point per 4\,mm cube. Each point gets a normal to estimate which direction a surface is facing.
    \item \textbf{Guess the motion:} Assume the camera repeats its last motion as a starting guess.
    \item \textbf{Align to last frame:} Pair each point with its nearest neighbour and shift the cloud to fit, targeting either the last frame or the last 10 frames.
    \item \textbf{Pose per frame:} Add each frame's motion to the previous pose to get \texttt{T\_cam\_world}.
\end{enumerate}

\subsection{COLMAP}
COLMAP uses texter to find patterns in the image and matches them across the frames. 
\begin{enumerate}
    \item \textbf{SIFT keypoints:} Find distinctive spots in every image.
    \item \textbf{Match neighbours (L and R):} Match the keypoints between each image and those within $\pm 12$ frames.
    \item \textbf{Add frames:} Start from a well-matched pair and add frames, finding each new frame's pose from the existing 3D points.
    \item \textbf{Bundle adjustment:} Optimise the camera positions and 3D points together to minimise the reprojection error.
    \item \textbf{Pose per frame:} Read out each frame's pose as \texttt{T\_cam\_world}.
\end{enumerate}

What the numbers say:

COLMAP has the smallest overall error and the right scale. The fixed 150 mm baseline gives it metric scale, and solving every frame together keeps drift down.
ICP is better over short stretches but drifts. With FoundationStereo depth and a local map it has the best motion error (2.5% over 50 mm) and orientation. Its overall error is still slightly higher, and its scale is 1% off, because small errors add up along the pass.
The depth source decides ICP. FoundationStereo roughly halves ICP's error compared with SGBM.
A local map beats frame-to-frame by about 2×.
Coloured ICP adds nothing: the grey levels change the result by less than 0.02 mm.
The scene only weakly pins down sliding. The translation constraint is 0.05–0.13. That's where ICP's drift comes from, and it will be worse on flat ice.
Things you should know before using this in the thesis:

I fixed two ICP problems after seeing this data. The first version let one wild step run away; it now rejects steps over 20 mm or 5° instead of repeating them. Its motion guess also repeated rotation, which grew about 1.5× per frame on the flat scene; it now extrapolates translation only. Both are documented in \texttt{icp\_poses.py}. Because they were found on s30, the ICP rows are tuned on the same data they're scored on. A second recording would make the comparison fairer.
The surroundings help both methods. Only about 14% of depth points lie on the board; the rest are bricks, the tray and sand. Ice will give both methods far less texture and shape, so treat these numbers as a best case.
The reference has its own noise (layout fit residual about 0.3 mm), so differences below that mean nothing. 17 of the 344 frames had no tag found, so their tags may still be visible to the estimators.
