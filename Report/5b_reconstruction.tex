\section{Reconstruction Steps}
\label{sec:ch5.reconstruction_steps}
There are numerous approaches to generate 3D reconstructions from stereo images. The methods
used within this report can be broken into three core steps \cite{szeliskiComputerVisionAlgorithmsa}: 
\begin{enumerate}
    \item \textbf{Depth per frame:} Stereo pairs are used to generate depth maps
    \item \textbf{Pose per frame:} The camera's position and orientation wihin the world frame
    \item  \textbf{Fusion:} Combining the sperate point clouds into a single object.
\end{enumerate}

As derived in \autoref{subsec:ch3.triangulation}, the depth $Z$ at any given point from its disparity using: 
\begin{equation}
    Z = \frac{fB}{d},
\end{equation}
Where $f$ is the focal length in pixels and $B$ is the baseline between the two cameras.
The equation is simple but the difficulty lies in determining $d$, which requires matching eaxh pixels in the left image to the same point
in the right image. Areas with little texture look near identicle between pixels, meaning many matches are possible. 
Patterns that repeat throughout the image produce many distinct matches that may all look correct. Parts of the scene may be visible from only one camera
but occluded from the other, resulting in no match at all. Underwater, these problems are made worse because scattering and attenuation 
reduce image contrast (TODO: CITE).
Three depth estimation methods are compared in this section, each approaching the correspondence problem differently.

\subsubsection{OpenCV SGBM}
% COmpares small blocks of pixels
Semi-Global Block Matching (SGBM) is a classical approach, used within this
project through OpenCV~\cite{opencv_sgbm}. For each pixel $\mathbf{p}$ and
candidate disparity $d$, it computes a matching cost $C(\mathbf{p}, d)$ by
comparing a small block around $\mathbf{p}$ in the left image with the block
shifted by $d$ in the right image, using the Birchfield--Tomasi
measure~\cite{birchfield1998}. Following
Hirschmüller~\cite[Eq.~(11)]{hirschmullerStereoProcessingSemiglobal2008}, it
then seeks the disparity map $D$ that minimises
\begin{equation}
    E(D) = \sum_{\mathbf{p}} \Big( C(\mathbf{p}, D_\mathbf{p})
    + \sum_{\mathbf{q} \in N_\mathbf{p}} P_1 \, T\big[|D_\mathbf{p} - D_\mathbf{q}| = 1\big]
    + \sum_{\mathbf{q} \in N_\mathbf{p}} P_2 \, T\big[|D_\mathbf{p} - D_\mathbf{q}| > 1\big] \Big),
    \label{eq:sgm_energy}
\end{equation}
where $N_\mathbf{p}$ are the neighbours of $\mathbf{p}$ and $T[\cdot]$ is 1
when its condition is true and 0 otherwise. The penalty $P_1$ allows
slow depth changes, while the larger $P_2$ minimises sudden jumps unless
the matching cost strongly supports them, such as at object edges. SGBM
approximates this minimisation by combining costs along multiple straight
paths through the image, with each pixel taking the disparity with the lowest
combined cost. SGBM is fast but relies on local pixel similarity, so it
struggles in regions of weak texture~\cite{kendallEndtoEndLearningGeometry2017}.

\subsubsection{Learnt Models}
Learnt models train on features from large datasets, replacing the designed matching costs with learnt features. Classical methods compare raw pixels which struggle in textureless
and repetitive envirnoments. Learnt models instead compare learnt feature descriptors of each image region,
allowing them to use wider semantic context. \cite{kendallEndtoEndLearningGeometry2017}.
The weakness however is that they depend heavily on training data \cite{wenFoundationStereoZeroShotStereo2025}.
For this reason, two different learnt models are tested, one leading general purpose model trained on a very large dataset, and a model designed specifically for underwater use. 
\autoref{fig:gcnet-architecture} shows the forward pass of GC-Net \cite{kendallEndtoEndLearningGeometry2017}, 
an early end-to-end learnt stereo model whose cost volume and soft argmin regression later models build on.

\textbf{FoundationStereo} \\
FoundationStereo is a Nvidia Labs general purpose model trained on roughly one million synthetic stereo pairs. 
It is designed to generalise to new scenes without any fine-tuning, making it zero-shot. It utilises a pretrained monocular depth model and compares every possible disparity
to build a cost volume. This volume is filtered with $3D$ conviltions and a mechanism that wieghs each pixel's candidate disparity against the others
The resulting disparity map is iteratively refined . Further details on the model architecture, training and benchamrk results are given
in the original paper \cite{wenFoundationStereoZeroShotStereo2025} and the official
implementation.\footnote{\url{https://github.com/NVlabs/FoundationStereo}}

\textbf{AquaStereo} \\
AquaStereo is a learnt model designed specifically for underwater reconstruction. Due to minimal underwater training data, it uses synthetic underwater stereo pairs, 
generated from an in-air dataset. During training, a teacher model sees the predicts disparity based on the clean terrestrial images, and AquaStereo leanrs to reproduce the
same predictions based low texture, turbid versions of the same images \cite{weiAquaStereoEnablingUnderwater2026}.

\subsection{Using Tag poses}
\label{subsec:ch5.tag_poses}
Apriltags are useful beyond creating an occlusion freindly calibration board. Placing apriltags within a scene
creates easily identifianble locations.. The camera's position can be calculated from the $3D$ positions of these corner locations and 
is implemented \texttt{tag\_poses.py}. The pose comes from
finding the rotation and translation that line the map up with the measured tag corners 
and creating an inverse of \cite{umeyamaLeastsquaresEstimationTransformation1991}.

\subsection{ICP (Iterative Closest Point)}
\label{subsec:ch5.icp}
% EXPLAIN
ICP (Iterative Closest Point), as explained in the \autoref{subsec:ch3.icp}, is a standard technique for aligning 3D point clouds \cite{besl1992}.
Here it is used to estimate camera motion from the shape of each frame's 3D point cloud. Each new frame's point 
cloud is shifted and rotated until it matches a reference cloud.
The amount of movement between clouds is the amount the camera has moved. 

First each frame's stereo depth map is converted into a 3D point cloud with
one point per valid pixel. Each cloud is reduced to one point per 4\,mm cube
(voxel), and each point is given a surface normal, estimating the direction
of its surface. The algorithm then works off a starting guess, assuming each
new frame repeats its last motion. It then pairs each point with its nearest
neighbour in either the last frame or the last 10 frames. It shifts and
rotates the cloud until it fits as closely as possible, repeating the pairing each
 time \cite{besl1992}. Each frame's motion is combined with the previous pose to generate
\texttt{T\_cam\_world}.

\subsection{COLMAP}
\label{subsec:ch5.colmap}
Unlike ICP, COLMAP uses texter rather than shape. It finds distinctive patterns in each image and matches across frames, then uses matches to recover both
the camera poses and the $3D$ positions of the matched points, a process called Structure from Motion (SfM) \cite{schonberger2016sfm}.
First, SIFT (Scale-Invariant Feature Transform) is used to find keypoints in both left and right images \cite{lowe2004}.  SIFT describes each keypoint with a vector that
summarises the brightness gradients in the surrounding patch, which stays
largely unchanged under changes in scale, rotation and lighting.  This means the same physical point can be recognised from differnt viewpoints. 
Keypoints are then matched between frames within $\pm 12$ frames of each other. The reconstruction is built incrementally.
As frames are added, bundle adjustment optimises camera poses and $3D$ points to minimise the reprojection error, the difference between
where each $3D$ point projects into an image and where the keypoint was actually detected \cite{triggs2000}. Each frame's pose is read out as \texttt{T\_cam\_world}.

\begin{figure}[H]
    \centering
    \includegraphics[width=1 \textwidth]{../Diagrams/COLMAPPipeline.pdf}
    \caption{COLMAP pose estimation: SIFT keypoints are matched between nearby frames and the poses are refined incrementally by bundle adjustment.}
    \label{fig:ch5.COLMAPPipeline}
\end{figure}

SIFT relies on texture to find keypoints meaning COLMAP can struggle on plain or blurred surfaces with few distinctive keypoints \cite{lowe2004}.

\section{Light the Fuse: Frame Integration and 3D Reconstrucion}
\label{sec:ch5.frame_integration}
% Intro to concept + Logic behind
Once each frame has both a depth map and a pose they can be joined into a single model.
Each depth map is converted into a point cloud, and transformed into the world frame using its pose.

The points are combined with a technique called voxel voting. The space around the object is divided into small
cubes (voxels), and each frame votes for every voxel its points fall into. A voxel is only kept if sufficient frames
agree that the surface lies ther. This rejects random points that only appear in a few frames. It also helps
ommitting small floating particles that are not set in the scene, keepipng only surfaces consistently seen from 
different viewpoints. 

The fused point cloud is then fused to remove the remaining outliers, and where relavent, aligns to the CAD model 
for scoring.

\subsection{TSDF (Truncated Signed Distance Function)}
\label{subsec:ch5.tsdf}
Curless and Levoy (1996) introduced the method, Newcombe et al. (2011), KinectFusion made it standard practice.

% Explain the premise - basic maths
% TODO: REWORD
The truncated signed distance function (TSDF) is the standard volumetric
representation for dense 3D reconstruction from depth data. Introduced by
Curless and Levoy~\cite{curless1996volumetric} and popularised for real-time
use by KinectFusion~\cite{newcombe2011kinectfusion}, it divides the scene
into a regular voxel grid. Each voxel $\mathbf{p}$ stores a signed distance
$F(\mathbf{p})$ to the nearest observed surface and a confidence weight
$W(\mathbf{p})$. Distances are positive in free space in front of the
surface and negative behind it, and are truncated to the interval
$[-\mu, \mu]$. Truncation confines updates to a narrow band around the
surface, so distant surfaces do not interfere with each other and unobserved
regions are left untouched. Each new depth frame $k$ produces a per-voxel
measurement $F_{R_k}(\mathbf{p})$ with weight $W_{R_k}(\mathbf{p})$. This
measurement is fused into the global model by a weighted running average:
\begin{equation}
  F_k(\mathbf{p}) =
  \frac{W_{k-1}(\mathbf{p})\,F_{k-1}(\mathbf{p}) + W_{R_k}(\mathbf{p})\,F_{R_k}(\mathbf{p})}
       {W_{k-1}(\mathbf{p}) + W_{R_k}(\mathbf{p})},
  \qquad
  W_k(\mathbf{p}) = \min\!\big(W_{k-1}(\mathbf{p}) + W_{R_k}(\mathbf{p}),\, W_{\max}\big).
  \label{eq:tsdf_fusion}
\end{equation}
Averaging over many frames suppresses sensor noise. The reconstructed
surface is recovered as the zero-level set $F(\mathbf{p}) = 0$, either by
raycasting or by extracting a mesh with Marching
Cubes~\cite{lorensen1987marching}. Because $F$ is continuous, interpolating
between voxels locates the surface to sub-voxel accuracy.

\subsection{What is tested}
\label{subsec:ch5.fusion_tested}

The depth map test (REF SECTION)) and (REF SECTION) produced a set of stereo depth maps and pose for each test data set.
The TSDF uses the same COLMAP genrated poses as COLMAP cannot take input poses ensuring all tests use the same set of input
poses. The test is run on S30 with 344 frame pairs (every fifth pair) with AprilTags masked out. Three different configurations are tested:


\begin{enumerate}
    \item \textbf{COLMAP pipeline:} PatchMatch stereo with geometric consistency, on the structure-from-motion model
    the poses come from. Every image, left and right (688 in all), gets its own depth map, matched against up to
    20 source views: its stereo partner first, then the frames closest to a 15\degree{} triangulation angle.
    $15\times15$~px matching window, full resolution (1600~px), minimum triangulation angle 1\degree. The depth
    maps are combined with COLMAP's stereo fusion, which keeps a point when at least 3 depth maps agree on it. The
    tag masks are applied in this fusion step.
    \item \textbf{TSDF with SGBM Tuned depth maps:} the tuned SGBM settings: 8-path mode (\texttt{MODE\_HH}),
    block 11, uniqueness 0, P1/P2 16/32, prefilter cap 63, half scale, speckle filter, left-right check 1~px. One
    depth map per stereo pair (344).
    \item \textbf{TSDF with FoundationStereo maps:} ViT-L, half scale, 32 iterations, left-right check 3~px,
    416~px disparity span, as in Section~\ref{sec:ch5.depth_test}. One depth map per stereo pair (344).
\end{enumerate}

Both TSDF runs use the same fusion settings: 1~mm voxels, a truncation distance of 4~mm, and a surface kept only
where at least 3 frames contributed, the TSDF counterpart of the voxel voting threshold. The truncation distance
has to exceed the depth noise and the disagreement between frames, which was around 4~mm on earlier scans.

To compare each result to the CAD models, the point clouds are first lined up with the board. The AprilTags on the
board give the true camera position in every frame, so the COLMAP camera positions are shifted and rotated to match
them, and every point cloud is moved the same way. The tags are only used for this lining up, not to build the
reconstructions. Each printed object is then cut out of the point cloud and compared with its CAD model.


Further testing on using less input frames is done.

\subsubsection{ACCURACY}
To measure accuracy, the 3D-printed objects are used, as their CAD models give a ground truth.
 The camera trajectory is aligned to the AprilTag poses so that every point cloud lies in the board frame. 
 Each object is cropped to a ±85 mm box around its known position, keeping only the points above the board 
 that belong to the object. The CAD model is fitted to these points by robust point-to-plane ICP. The fit is 
 restricted to in-plane position and yaw, because the object rests flat on the board, so height and tilt errors
  cannot be fitted away. The board is first levelled in a ring 10–40 mm around each object, so that small errors in
   the tag-defined board plane are not counted against the object. Accuracy is then measured as the signed distance
    from each point to the CAD surface. The median absolute distance is the main measure, because it is robust to outliers.
     The 95th percentile and the RMS show the tails,m and coverage (the share of the visible CAD surface with a point within 2 mm) 
     shows how complete the reconstruction is.

All three methods recover the overall shape of each ice target, but \autoref{fig:ch5.fusion_oblique} 
shows clear differences in how cleanly they do so. COLMAP produces the most stray points. Scattered points float above every target, and 
on the overhang, streaks of points hang down from the edges of the top block.
 Its surfaces are also rougher, with the pyramid steps and the cubes blurred by noise.
  TSDF with SGBM depth maps is cleaner but less complete. It captures surfaces facing the camera, 
  such as the tops of the pyramid steps and the overhang, but loses the steep faces between them, 
  leaving holes in the base and gaps between the steps. It also merges the cubes into a single patch, a
  nd adds a false sheet of points over part of the wave. TSDF with FoundationStereo gives the cleanest result on every target.
   The pyramid steps are sharp and flat, each cube is separated from its neighbours, the waves form smooth continuous ridges, 
   and the overhang is recovered with its side walls. This comparison is qualitative, since there is no CAD model for the ice targets.


No fusion method performed best on every object. TSDF with FoundationStereo depth maps gave the 
most complete and most accurate reconstructions of both pyramids, and the cleanest results on all four 
ice targets. However, it was the least accurate on the egg carton, where it sits 15--20\,mm below the designed curve, 
so it can misjudge smooth, low-texture surfaces. SGBM achieved a low median error on the pyramid only by reconstructing
 the easiest 17\,\% of it, which shows that accuracy must be read together with coverage. Coverage was low for every method, 
 at most 44\,\%, because a single pass sees steep and hidden faces poorly. All three methods had median errors of 2--4\,mm and sat 2--4\,mm 
 above the CAD surface on the pyramid flanks. As they share the same COLMAP poses (2.4\,mm position error) and calibration, this common error 
 most likely comes from those inputs rather than from the fusion itself. TSDF with FoundationStereo is therefore recommended as the default fusion
  method, with the caveat that smooth curved ice should be checked. A benefit of having all this done in post, is that for real ice deployments,
  both methods can be retested on the same data.

\section{Testing Full pipeline}
\label{sec:ch5.testing_full_pipeline}
% TIME for frame
The final pipeline configuration was FoundationStereo for depth estimation, COLMAP for pose estimation and TSDF
for fusion. In a real deployment the ROV passes the ice quickly, so each surface is seen in only a limited number
of frames. It is therefore important to know how many frames a reconstruction needs. Reconstruction runs in
post-processing, so speed is less critical than in a real-time system, but the time per run is still not
negligible. The hardware requirements also need to be understood: FoundationStereo runs on the GPU, while
COLMAP and TSDF fusion are limited by memory, so the peak GPU memory and RAM of each stage determine what
computer the pipeline needs and how large a scan it can process. To quantify all three, a sweep was run over the
number of frames given to the pipeline, recording the time and peak compute use (GPU memory, RAM and CPU) of
each stage and the resulting coverage of the ice.

Each frame count was run through the whole pipeline: COLMAP structure-from-motion was repeated on every subset,
because pose estimation is the stage most likely to fail when frames are sparse. The sweep was run on
[recording] (151 frames) over:
\begin{itemize}
    \item \textbf{Frame count:} every $N$\textsuperscript{th} frame for $N = 1, 2, 3, 4, 6, 8, 12, 16$, giving
    151 down to 10 frames.
    \item \textbf{Depth source:} FoundationStereo, with tuned SGBM as a lower-cost alternative, both fused with
    TSDF at the poses COLMAP produced for that subset.
\end{itemize}
For each subset, the following were measured: the number of frames COLMAP registered, the pose error against
the AprilGrid reference, the coverage of the ice region, the cloud-to-cloud distance to the all-frames
reconstruction, and the wall time, peak RAM and peak GPU memory of each stage. All runs were made on a laptop
with an NVIDIA RTX 5060 Laptop GPU (8~GB) and 30~GB of RAM.
