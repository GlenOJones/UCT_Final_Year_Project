\subsection{Seeing Double: Depth from a Stereo Camera}
% The disparity equation, the correspondence problem, and then SGBM, FoundationStereo and AquaStereo
% Maths done in intro depth per pixel
% Rough explain OpenCVSGBM, FoundationStereo, AquaStereo, COLMAP (different approach)
% Show breif comparison with analysis - NOt sure what metric

As explained in (Ref theory review), the depth $Z$ at any given point from its disparity using: 
\begin{equation}
    Z = \frac{fB}{d},
\end{equation}
The equation is simple but the difficulty lies in determining $d$, which requires matching pixels between the left and right image. 
While it may be visually easy to distinguish, this correspondance is algorithmically difficult. Areas with little texture look near identicle between pixels, meaning
many matches are possible. Patterns that repeat throughout the image produce many distinct matches that may all look correct. Parts of the scene may be visibnle from only one camera
but occluded from the other, resulting in no match at all. These issues are worsened underwater by turbity and the low texture Ice. 
Three different depth methods are compared in this report, each approaching the correspondence problem in different ways.

% ~~~~~ Subsubsection: OpenCV SGBM ~~~~~
\subsubsection{OpenCV SGBM}
Semi-Global Block Matching is a classical approach.
% COmpares small blocks of pixels
Semi-Global Block Matching (SGBM) is a classical approach and is implemented through OpenCV. It compares small blocks of picels along each row, compuuting a matching cost for 
every candidate disparity. It then joins these costs along several directions, penalising jumps in disparity so that neighouring pixels get similar depths SGBM runs quickly 
and relies purely on the local pixel similarity.

\subsubsection{Learnt Models}
Learnt stere models train on large datasets, replacing the specific matching costs with learnt features. Instead of comparing raw pixel values, learn descriptions of each image
region are compared. This allows them to use more context such as the objects shape and scene layout. The weakness however is that they are only as good as their training data. 
For this reason, two different learnt models are tested, one currently leading industry trained over large data set, and one specifically designed for underwater use. 

\textbf{FoundationStereo} \\
FoundationStereo is a deep learning model trained on a large synthetic dataset. It is designed to generalise to new scenes without any fine-tuning, making it zero-shot. 
It builds a cost volune from the learnt feautres, strengthened with "priodrs" from monocoular depth model, and iteratively refines the disparity estimate. 

\textbf{AquaStereo} \\
AquaStereo is a learnt model aimed specifically at underwater reconstruction. It is trained on synthetic underwater stereo pairs, generated from a terrestrial dataset.
It transfers geometric knowledge from a teacher model traiend on clean images, and uses featurees designed to remain stable in turbid, low-texture conditions.

\subsection{ICP (Iterative Closest Point)}
% EXPLAIN
ICP (Iterative Closest Point), as explained in the introduction, is a standard technique for aligning 3D point clouds.
It uses the shape of each frame's 3D point cloud to estimate camera motion. Each cloud is shifted and rotated until it matches the previous one.
The amount of movement between clouds is the amount the camera has moved. First each frame's stereo depth map is converted into a $3D$ point cloud with one point per
valid pixel. Each cloud is reduced to one point per 4mm cube and each remaining point is given a normal, estimating the direction of its surface. The algorithm then works
off a starting guess, assuming each new frame repeats its last motion. It then pairs each point with its nearest neighbour in the either the last fram or from within the last 
10 frames. It shifts the cloud undtil it fits as closely as possible. Each frame's motion is added to the previous pose to generate \texttt{T\_cam\_world}.

\subsection{COLMAP}
COLMAP uses texter to find patterns rather than shape. It finds distinctive patterns in each image and matches across frames, a process called Structure from Motion (SfM).
First, SIFT (Scale-Invariant Feature Transform) is used to find keypoints in both left and right images. SIFT describes each keypoint with a vector that "summarises the brightness gradients
in the surrounding pathc, which staus largely unchanged under changes in scale, rotatio and lighting. This means the same physical point cna be recognised from differnt viewopoints. 
Key points are then matched within $\pm 12$ frames. As frames are added, bundel adjustment optimises camera postitions and 3D points to minimise reprojection error. The difference between
where each $3D$ point projects into an image and where the keypoint was actually detected. Each frame's pose is read out as \texttt{T\_cam\_world}.

SIFT relies on texture to find keypoints meaning COLMAP can struggle on plain or blurred surfaces.

\section{Fusing Frames}
Once each frame has both a depth map and a pose they can be joined into a single model.
Each depth map is converted into a point cloud, and transformed into the world frame using its pose.

The points are combined with a technique called voxel voting. The space around the object is divided into small
cubes (voxels), and each frame votes for every voxel its points fall into. A voxel is only kept if sufficient frames
agree that the surface lies ther. This rejects random points that only appear in a few frames. It also helps
ommitting small floating particles that are not set in the scene, keepipng only surfaces consistently seen from 
different viewpoints. 

The fused point cloud is then fused to remove the remaining outliers, and where relavent, aligns to the CAD model 
for scoring.

What the numbers say:

COLMAP has the smallest overall error and the right scale. The fixed 150 mm baseline gives it metric scale, and solving every frame together keeps drift down.
ICP is better over short stretches but drifts. With FoundationStereo depth and a local map it has the best motion error (2.5% over 50 mm) and orientation. Its overall error is still slightly higher, and its scale is 1% off, because small errors add up along the pass.
The depth source decides ICP. FoundationStereo roughly halves ICP's error compared with SGBM.
A local map beats frame-to-frame by about 2×.
Coloured ICP adds nothing: the grey levels change the result by less than 0.02 mm.
The scene only weakly pins down sliding. The translation constraint is 0.05–0.13. That's where ICP's drift comes from, and it will be worse on flat ice.
Things you should know before using this in the thesis:

I fixed two ICP problems after seeing this data. The first version let one wild step run away; it now rejects steps over 20 mm or 5° instead of repeating them. Its motion guess also repeated rotation, which grew about 1.5× per frame on the flat scene; it now extrapolates translation only. Both are documented in \texttt{icp\_poses.py}. Because they were found on s30, the ICP rows are tuned on the same data they're scored on. A second recording would make the comparison fairer.
The surroundings help both methods. Only about 14% of depth points lie on the board; the rest are bricks, the tray and sand. Ice will give both methods far less texture and shape, so treat these numbers as a best case.
The reference has its own noise (layout fit residual about 0.3 mm), so differences below that mean nothing. 17 of the 344 frames had no tag found, so their tags may still be visible to the estimators.
